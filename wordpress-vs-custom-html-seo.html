WordPress vs custom HTML for SEO:
what actually matters

Sergio Carrión · 5 min read · SEO Strategy

Every few months someone publishes a new take on "WordPress vs static HTML for SEO" and the debate rages again. Custom HTML is faster. WordPress has better plugins. Static sites win on Core Web Vitals. WordPress wins on content management.

Most of these arguments are missing the point. After building and maintaining WordPress sites professionally for US clients, here's the honest answer: the platform is not the ranking factor. Your execution is.

What Google actually ranks on

Google evaluates pages on a handful of things that have nothing to do with whether you used WordPress or wrote raw HTML:

  • Page experience — Core Web Vitals (LCP, CLS, INP), mobile usability, HTTPS
  • Content relevance — does this page actually answer the search query better than competitors?
  • Authority — do other trustworthy sites link to you?
  • Technical accessibility — can Googlebot crawl, render, and index your pages without issues?

None of those say "WordPress" or "custom HTML." A well-optimized WordPress site will outrank a poorly-built custom HTML site every time, and vice versa.

On a head-to-head technical comparison of a clean build, custom HTML wins on performance. This portfolio you're reading right now is pure HTML — it scores 98+ on mobile PageSpeed with zero configuration.

Where WordPress wins

The performance advantage of custom HTML disappears the moment you need to manage content at scale. Consider what WordPress gives you:

  • Non-technical editors can publish content without touching code — this matters enormously for blog-driven SEO strategies
  • Programmatic SEO is possible with custom post types and dynamic templates — you can generate hundreds of location pages from a single template
  • Yoast/RankMath integration handles meta tags, sitemaps, and schema markup with a UI that your client can use themselves
  • WooCommerce, membership sites, complex forms — things that would take weeks to build from scratch
The real question

The question isn't "which platform is better for SEO." The question is: "which platform lets me build and maintain the best possible version of this site for this use case?" For most business sites that need regular content updates, that's WordPress — but only if it's configured correctly.

How to make WordPress perform like custom HTML

If you're on WordPress and want to close the performance gap, these are the levers that actually move the needle:

  1. Full-page caching — WP Rocket or W3 Total Cache. Without this, every request runs PHP. With it, WordPress serves static HTML files identical to a custom site.
  2. Disable plugins on pages that don't need them — Asset CleanUp lets you disable scripts and styles per post type. A homepage doesn't need WooCommerce JavaScript.
  3. Use a lightweight theme as a base — GeneratePress or Kadence. Both have sub-50KB front-end weight out of the box.
  4. Serve static assets from a CDN — Cloudflare free tier is enough for most sites. This handles global latency and TTFB.
  5. Eliminate render-blocking resources — WordPress has a bad habit of loading everything in the head. Move non-critical CSS and JS to deferred or async loading.

A WordPress site with these five things in place will score 90+ on mobile PageSpeed. That's equivalent to a well-built custom HTML site — and it comes with a CMS your client can actually use.

The bottom line

Platform choice is a decision about workflow and maintainability, not a SEO decision. Google doesn't rank WordPress or custom HTML — it ranks pages that load fast, are crawlable, contain relevant content, and have earned authority.

Stop debating the platform. Start optimizing what the platform produces.

What I do in practice

For client business sites that need content updates: WordPress with WP Rocket, a lightweight theme, and a proper technical SEO setup. For my own tools, demos, and portfolio: custom HTML or static generation. The right tool for the job — not dogma.
