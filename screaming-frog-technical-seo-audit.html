Setting up Screaming Frog for a
full technical SEO audit

Sergio Carrión · 6 min read · Technical SEO

Screaming Frog is the most powerful SEO crawling tool available — and most people use about 20% of what it can do. They run a crawl with default settings, look at the 404 tab, and call it an audit. That's not an audit. This is the configuration I use on every new site before I touch anything.

I'll cover the setup, the custom extractions that catch what the default tabs miss, and the exact order in which I review the reports.

Before you crawl: configuration that matters

The default settings are fine for a basic crawl. But for a real audit, change these before you start:

Crawl settings

// Configuration → Speed Crawl Speed: 5–10 threads // Don't hammer shared hosting Crawl Delay: 0.5s // Polite crawling Max URL: Leave unlimited for full audits // Configuration → Spider Crawl linked XML sitemaps: YES Check source code: YES // Catches noindex in JS Crawl outside of start: NO // Stay on domain Respect nofollow: NO // Audit all links

Connect Google Search Console

This is the step most people skip. Go to Configuration → API Access → Google Search Console and connect your account. This pulls real click and impression data into the crawl — so you can see which pages get traffic and which are crawled but never clicked. Game-changing for prioritization.

Pro tip

If the site has a staging environment, crawl that first. You can test fixes without affecting the live site's crawl budget.

Custom extractions — what the default tabs miss

The default tabs show you titles, meta descriptions, response codes, and headings. Useful, but incomplete. Custom extractions are where you find the issues that no one else is catching.

Go to Configuration → Custom → Extraction and add these:

// Extract 1: Canonical URL (detect self-referencing vs wrong canonicals) Name: Canonical Extract: XPath XPath: //link[@rel='canonical']/@href // Extract 2: noindex check (catches JS-rendered noindex) Name: Robots Meta Extract: XPath XPath: //meta[@name='robots']/@content // Extract 3: H1 count (detect pages with multiple H1s) Name: H1 Count Extract: CSSPath CSS: h1 Extract: Count // Extract 4: Structured data presence Name: Schema Type Extract: XPath XPath: //script[@type='application/ld+json']

The audit order — where to look first

After the crawl finishes, I review tabs in this exact order. The reason for the order: critical technical blockers first, then content issues, then optimization opportunities.

01
Response Codes → 3xx and 4xx
Redirect chains longer than 2 hops waste crawl budget and lose link equity. Broken links (4xx) hurt UX and can cause crawl errors in GSC. Fix these first.
02
Directives → Indexability
Filter by "noindex" and cross-reference with GSC. You'd be surprised how many important pages are accidentally blocked. Check your Custom Extraction "Robots Meta" column here.
03
Page Titles → Duplicates and missing
Sort by "Occurrences" to find duplicate titles. Filter for "Missing" to catch pages with no title at all. Both are easy wins.
04
Canonicals → Self-referencing check
Use your custom "Canonical" extraction. Every indexable page should have a canonical pointing to itself. Pages with no canonical or a canonical pointing to a different URL need investigation.
05
Images → Missing alt text and oversized files
Filter for images over 100KB and images with no alt text. Both affect performance and accessibility rankings.
06
Internal → Orphan pages
Go to Reports → Crawl Analysis → Orphan pages. These are URLs in your sitemap that have zero internal links pointing to them. Google can find them but won't assign much authority.

What each tab status color means

When I export the full report, I color-code issues into three priority tiers:

Fix immediately Noindex on key pages Redirect loops Missing canonicals
Fix this sprint Duplicate titles Redirect chains 3+ Missing H1
Optimization Title length Missing alt text Schema markup

Saving your configuration

Once you've set up custom extractions and connected GSC, save the configuration: File → Configuration → Save. Name it per client. Next time you audit that site, load the saved config and run the crawl — no setup needed.

Final thought

A Screaming Frog audit is a starting point, not a final answer. The tool tells you what is wrong — you still need to understand why it's wrong and what the fix will cost vs. what it will gain. Prioritize by potential impact, not by the number of issues in a tab.
